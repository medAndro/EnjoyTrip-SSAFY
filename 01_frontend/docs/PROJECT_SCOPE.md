# 범위 검토 — 두 사람 병렬 3시간

## 기준

사용자 요청: 두 사람이 약 3시간 동안 학습 코드를 직접 구현한다. 필수와 추가 요구사항을 우선하며, AI가 페이지별 샘플 코드·레이아웃·아이콘과 기본 골격을 준비한다.

검토 자료는 저장소 `교안/`의 01~08 정리 문서와 프로젝트 PDF다. 교안의 AI 시스템 프롬프트 예시는 학습 자료로 읽었으며 현재 사용자 요청을 지원 경계로 삼았다.

## 교안과 직접 구현할 내용

| 교안 | 프로젝트에서 연습할 내용 |
| --- | --- |
| 01 HTML | label/name/required, 의미 있는 구조, 링크와 버튼 구분 |
| 02 CSS 1 | 선택자, 색·여백, 공통 변수, 오류/선택 상태 |
| 03 CSS 2 | Flex/Grid와 모바일 한 열 배치 |
| 04 JS Basic | 함수, 배열/객체, 조건, 모듈 |
| 05 DOM·Storage | 요소 생성/삭제, dataset, JSON 저장·복원 |
| 06 이벤트·BOM | submit/change/click, 폼 검증, 페이지 이동 |
| 07 AJAX | fetch, response.ok, async/await, 실패 처리 |
| 08 관통 | 데이터→목록/지도, 좌표와 SDK 준비 시점 |

지도와 비동기도 교안 안의 내용이다. 다만 3시간 제한 때문에 SDK/마커/주소 변환 기반 코드를 AI가 제공한다. 두 사람은 데이터 전달과 화면 동기화를 구현하고, 제공 코드의 lat/lng 순서·마커 제거·완료 대기 원리를 읽는다. 이미지 축소와 canvas는 이번 핵심 학습에서 제외하여 AI helper로 처리한다.

## 3시간 목표

| 요구사항 | 실습에서 구현할 최소 동작 | 단순화 |
| --- | --- | --- |
| F101 지역 관광지 | 로컬 JSON fetch, 지역별 목록·지도 | 3개 지역, 실제 공공 API는 후속 |
| F102~F103 유형 조회 | 7개 유형 필터, 상세 표시 | 페이징·복잡한 검색 없음 |
| F107 회원 관리 | 가입/조회/닉네임·이메일 수정/탈퇴 | 샘플 회원, 최소 필드 |
| F108 로그인 | 로그인/로그아웃/데모 비밀번호 재설정 | 실제 메일·인증 서버 없음 |
| F104 여행 계획 | 관광지 추가/삭제, 순서, 날짜·경비·메모, 저장/복원 | 회원당 1개, 위·아래 버튼 |
| F105 Hotplace | 사진/위치/유형/방문일/설명 등록, 내 목록/지도, 복원 | 좌표 직접 입력, 회원당 최대 3개 |

선택한 관광지 ID를 sessionStorage 초안에 넣어 여행 계획 화면에 전달한다. 여행 계획은 제목·기간과 방문 배열을 저장하고 저장 버튼으로 덮어쓴다. 새로고침 후 자신의 계획을 자동 불러온다. 여러 계획 목록·드래그앤드롭·도로 경로 계산은 넣지 않는다.

Hotplace는 사진 선택 시 제공 helper를 호출한다. 위도·경도를 직접 입력하는 방식으로 시작한다. 여유가 있으면 제공 주소 변환 helper를 연결한다. 샘플 JSON은 가상 주소이므로 주소 검색에 사용하지 않는다.

## 명세를 충족했다고 과장하지 않을 항목

- F101의 최종 명세는 한국관광공사 데이터 활용이다. AI 가상 JSON으로 조회했다고 실 API 연동 완료가 되지는 않는다.
- F104의 추가 화면 설명에는 드래그앤드롭이 있다. 버튼 순서 변경은 3시간 실습용 축소안이다.
- F105의 사진/지도 표현은 지도 키 설정과 등록 좌표 전달까지 확인해야 완료다. 키가 없으면 목록·저장만 완료했다고 기록한다.
- PDF는 Bootstrap 활용을 명시한다. 현재는 사용자 요청에 따라 직접 CSS를 썼다. 해당 제출 조건이 유지되면 추가 적용한다.

따라서 3시간 목표는 **필수·추가 기능을 모두 경험하는 최소 구현**이다. 명세 전체를 완성해야 한다면 위 항목에 후속 시간이 필요하다.

## 이번에 제외

뉴스 크롤링(F106), 공지(F109), 게시판(F110), 기타 날씨/일출/충전소, 실제 DB·Spring·Vue·메일·사진 서버, 여행 경로 최적화.

## AI 제공 / 사람이 작성

AI가 작성: 폴더, 7개 정적 HTML, 샘플 CSS, 로컬 SVG 2개, 가상 관광지 21개, 상수, 임시 폼 제출 보호, 지도 SDK 연결 helper, 사진 축소 helper, 본 문서.

사람이 작성: fetch/필터/DOM, 폼 검증, 회원 및 세션, Storage CRUD, 일정 배열 순서/합계/저장, 사진 이벤트와 미리보기/등록, helper에 데이터를 넘기는 연결. UI는 완성 레퍼런스를 활용하되 각자 카드/오류 메시지 등 한 부분은 직접 수정하여 CSS를 연습한다.

## 완료 확인 — 3시간 마지막 25분

1. 가입→로그인→새로고침→정보 수정→로그아웃을 확인한다.
2. 다른 회원으로 로그인하면 이전 회원 계획/Hotplace를 관리할 수 없어야 한다.
3. 7개 유형 필터와 검색 결과 0건을 확인한다.
4. 관광지 추가→순서 변경→경비 입력→저장→새로고침 뒤 복원을 확인한다.
5. 사진 선택→미리보기→등록→새로고침 뒤 복원을 확인한다.
6. 탈퇴 시 해당 회원의 저장 데이터와 초안을 정리한다.
7. 작은 화면과 Console에서 넘침/오류를 확인한다.
8. 실제 구현한 화면을 캡처하고 미완료 항목을 README에 기록한다.

기능 확인 전에는 레퍼런스 카드/샘플 일정 항목을 실제 저장 결과로 사용하지 않는다. 실패를 성공 메시지로 숨기지 않는다. 일정 상한은 최대 5개 방문, 사진 상한은 회원당 3개로 시작한다.
