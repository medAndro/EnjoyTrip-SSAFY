# A·B별 상세 구현 작업

A는 관광지 조회와 여행 계획, B는 회원 기능과 Hotplace를 맡습니다. 각자 자신의 화면에서 입력 → 이벤트 → 데이터 처리 → 화면 표시 → 저장까지 연결합니다.

기존 HTML·CSS는 레퍼런스로 활용하고, 아래 순서대로 JavaScript를 작성합니다. 두 사람이 병렬로 약 3시간 동안 구현할 최소 범위를 기준으로 합니다.

## A: 관광지 조회 + 여행 계획

주요 파일은 `js/data.js`, `js/attractions.js`, `js/plans.js`와 해당 HTML·CSS입니다.

| 순서 | 구체적인 작업 | 완료 기준 |
| --- | --- | --- |
| 1 | 관광지 JSON 불러오기 | 받은 배열을 Console에서 확인 |
| 2 | 관광지 목록 표시 | 샘플 카드 대신 JSON 데이터 표시 |
| 3 | 지역·유형 필터 | 선택 조건에 맞는 관광지만 표시 |
| 4 | 상세 화면 연결 | 클릭한 관광지 정보가 모달에 표시 |
| 5 | 지도 helper 연결 | 검색 목록과 지도 위치가 일치 |
| 6 | 여행 계획에 관광지 추가 | 선택한 관광지가 계획 화면에 표시 |
| 7 | 일정 편집 | 삭제·순서 변경·경비 입력 가능 |
| 8 | 저장·복원 | 새로고침 후 본인 계획 유지 |

### A-1. 관광지 JSON 읽기

`data.js`에서 `loadAttractions()`를 작성하고 다른 파일에서 사용할 수 있도록 내보냅니다.

```text
JSON URL로 fetch 요청
→ 응답 성공 여부 확인
→ JSON을 배열로 변환
→ 배열 반환
→ 실패하면 오류 전달
```

- [x] JSON을 읽고 받은 배열을 Console에서 확인한다.
- [x] HTTP 요청 실패를 확인하고 오류를 전달한다.
- [x] `attractions.js`에서 함수를 가져와 완료를 기다린다.

### A-2. 관광지 목록 만들기

`attractions.js`에서 기존 샘플 카드들을 지우고, 받은 관광지 배열을 순회하며 카드 요소를 생성합니다. 이름·주소·유형을 표시하고, 카드나 상세 버튼에 관광지 ID를 연결합니다.

```text
관광지 배열 받기
→ 목록 영역 비우기
→ 관광지마다 카드 생성
→ 이름·주소·유형 채우기
→ 목록에 추가
```

- [x] 정적 샘플 카드가 실제 결과에 섞이지 않도록 제거한다.
- [x] 요소를 생성하고 텍스트를 채워 목록에 추가한다.
- [x] 상세에서 사용할 관광지 ID를 `dataset`에 연결한다.

### A-3. 검색 폼 연결

제출 이벤트에서 기본 동작을 취소하고 지역·유형 값을 읽습니다. `filter()`로 결과 배열을 만든 뒤 목록을 다시 표시합니다.

- [x] 먼저 지역 필터를 구현한다.
- [x] 관광지·숙박·음식점·문화시설·공연·행사·여행코스·쇼핑의 7개 유형 필터를 구현한다.
- [x] 전체 지역·전체 유형 선택도 처리한다.
- [x] 결과가 0개이면 이전 카드를 지우고 “검색 결과가 없습니다”를 표시한다.
- [x] 키워드는 시간이 남으면 추가한다.

### A-4. 상세 모달 연결

클릭한 버튼의 ID로 관광지를 찾습니다. 이름·설명·주소를 모달에 넣고 엽니다.

- [x] 클릭한 관광지 ID를 읽는다.
- [x] 배열에서 해당 관광지를 찾는다.
- [x] 상세 내용을 채우고 모달을 연다.
- [x] 닫기 버튼을 연결한다.

### A-5. 지도 helper 연결

제공된 `createMap()`으로 지도 컨트롤러를 준비하고 검색 결과 배열을 `updatePlaces()`에 전달합니다. 키가 없으면 컨트롤러가 `null`이므로 지도 호출을 건너뜁니다.

직접 지도 SDK를 다시 작성할 필요는 없습니다. **어떤 검색 결과를 언제 지도에 전달할지**를 구현합니다.

- [ ] 지도 컨트롤러를 준비한다.
- [ ] 목록과 지도에 같은 검색 결과 배열을 전달한다.
- [ ] 결과가 없을 때 이전 마커가 정리되는지 확인한다.
- [ ] 지도를 사용할 수 없어도 목록 조회는 계속 가능하도록 한다.

### A-6. 관광지를 여행 계획에 추가

상세의 ‘일정에 추가’에서 로그인 여부를 확인하고 관광지 ID를 `planDraft`에 저장합니다. 같은 관광지는 중복 추가하지 않습니다.

- [ ] 현재 회원을 확인한다. 로그인 전이면 로그인 안내를 표시한다.
- [ ] 초안에 관광지 ID를 추가한다.
- [ ] 계획 화면에서 초안 ID로 관광지 정보를 찾는다.
- [ ] 기존 일정에 새로운 관광지만 추가하고, 반영한 초안은 정리한다.

### A-7. 일정 배열 편집

`plans.js`에서 회원당 계획 1개, 방문지 최대 5개로 구현합니다.

- [ ] 여행 제목·시작일·종료일·전체 메모를 입력받는다.
- [ ] 각 방문의 날짜·경비·메모를 입력받는다.
- [ ] 항목 삭제를 구현한다.
- [ ] 위·아래 버튼으로 배열 순서를 변경한다.
- [ ] 경비를 숫자로 변환하여 합계를 표시한다.
- [ ] 시작일이 종료일보다 늦거나, 방문일이 기간 밖이거나, 경비가 음수이면 저장하지 않는다.
- [ ] 방문 시간 입력은 여유가 있을 때 연결한다.

방문 순서는 화면만 바꾸지 않고 `items` 배열의 순서를 바꿉니다. 드래그앤드롭은 후속 작업입니다.

### A-8. 계획 저장·복원

`ownerId`가 현재 회원인 계획을 찾아 덮어쓰거나 새로 추가합니다. 다른 회원의 계획은 보존합니다.

- [ ] 현재 회원 ID를 계획에 포함한다.
- [ ] 기존 계획이 있으면 해당 회원의 계획만 덮어쓴다.
- [ ] 화면을 다시 열면 현재 회원의 계획을 불러온다.
- [ ] 새로고침 후 내용·순서·경비가 유지되는지 확인한다.
- [ ] 여행 삭제 버튼으로 현재 회원의 계획만 제거한다.

## B: 회원 기능 + Hotplace

주요 파일은 `js/storage.js`, `js/session.js`, `js/members.js`, `js/common.js`, `js/hotplaces.js`와 해당 HTML·CSS입니다.

| 순서 | 구체적인 작업 | 완료 기준 |
| --- | --- | --- |
| 1 | 공통 저장 함수 | 배열·객체 저장과 복원 가능 |
| 2 | 세션 함수 | 현재 로그인 회원 확인 가능 |
| 3 | 회원가입 | 검증 후 회원 저장 |
| 4 | 로그인·로그아웃 | 페이지 이동 후에도 메뉴 상태 일치 |
| 5 | 조회·수정·탈퇴 | 현재 회원 정보만 변경 |
| 6 | 데모 비밀번호 재설정 | 계정 확인 후 새 값 저장 |
| 7 | 사진 미리보기 | 선택한 사진이 화면에 표시 |
| 8 | Hotplace 등록·복원 | 본인 기록이 새로고침 후 유지 |

### B-1. 공통 저장 함수

A도 사용할 수 있도록 `readJSON()`과 `writeJSON()`을 작성하고 내보냅니다.

```text
읽기: 저장값 조회 → 없으면 기본값 → JSON.parse → 반환
쓰기: JSON.stringify → 저장
```

- [ ] 저장값이 없으면 지정한 기본값을 반환한다.
- [ ] 배열·객체를 문자열로 저장하고 다시 복원한다.
- [ ] 잘못된 JSON이나 저장 실패는 오류로 전달한다.
- [ ] `localStorage.clear()`는 사용하지 않는다.
- [ ] 두 함수가 완성되면 A에게 먼저 알린다.

### B-2. 세션 함수

`getCurrentUser()`, `setSession()`, `clearSession()`을 구현합니다.

```text
세션의 userId 읽기
→ 회원 배열에서 찾기
→ 있으면 ID·닉네임·이메일 반환
→ 없으면 null 반환
```

- [ ] 세션에는 회원 ID만 저장한다.
- [ ] 현재 회원 조회 결과에 데모 비밀번호를 포함하지 않는다.
- [ ] 로그인 전환·로그아웃 때 여행 계획 초안도 정리한다.
- [ ] 세션의 회원이 더 이상 존재하지 않는 상황을 처리한다.

### B-3. 회원가입

아이디·닉네임·샘플 이메일·데모 비밀번호를 읽고 검증합니다.

- [ ] 필수 입력 여부를 확인한다.
- [ ] 기존 회원과 아이디가 중복되는지 확인한다.
- [ ] 비밀번호와 확인 값이 일치하는지 확인한다.
- [ ] 통과하면 회원 배열에 추가하고 저장한다.
- [ ] 실패하면 해당 입력 오류를 보여 준다.

실제 개인정보나 실제 서비스의 비밀번호 대신 학습용 가상 정보를 사용합니다.

### B-4. 로그인·로그아웃·공통 메뉴

로그인 입력을 회원 배열과 대조하고 성공하면 세션을 설정합니다. `common.js`에서는 현재 회원에 따라 로그인·회원가입 링크 또는 회원명·로그아웃 버튼을 표시합니다.

- [ ] 올바른 계정으로 로그인할 수 있다.
- [ ] 잘못된 계정은 세션을 만들지 않고 오류를 표시한다.
- [ ] 로그인 상태에 따라 공통 메뉴를 변경한다.
- [ ] 로그아웃 시 세션·초안을 정리하고 메뉴를 갱신한다.
- [ ] 새로고침과 페이지 이동 후에도 상태가 일치하는지 확인한다.

### B-5. 내 정보 조회·수정·탈퇴

로그인하지 않았다면 로그인 안내를 표시합니다. 로그인 상태라면 현재 회원 정보를 입력칸에 채웁니다.

- [ ] 현재 회원의 아이디·닉네임·샘플 이메일을 표시한다.
- [ ] 아이디는 유지하고 닉네임·샘플 이메일만 수정한다.
- [ ] 수정 후 저장하고 공통 회원명도 갱신한다.
- [ ] 탈퇴 확인 후 해당 회원의 데이터를 정리한다.

```text
현재 회원 제거
→ 해당 ownerId의 계획 제거
→ 해당 ownerId의 Hotplace 제거
→ 세션과 초안 제거
```

다른 회원의 데이터는 보존합니다. 저장 실패를 성공으로 표시하지 않습니다.

### B-6. 데모 비밀번호 재설정

아이디와 샘플 이메일이 같은 회원을 찾고, 새 비밀번호와 확인 값이 일치하면 저장합니다.

- [ ] 아이디·샘플 이메일이 일치하는 회원을 찾는다.
- [ ] 새 비밀번호와 확인 값을 검증한다.
- [ ] 해당 회원의 데모 비밀번호만 변경한다.
- [ ] 변경된 값으로 다시 로그인할 수 있는지 확인한다.

실제 이메일 발송은 구현하지 않습니다.

### B-7. 사진 선택·미리보기

파일 입력의 `change` 이벤트에서 제공된 `preparePhoto(file)`을 호출합니다. 완료를 기다린 뒤 반환된 이미지 주소를 미리보기의 `img.src`에 넣습니다.

- [ ] 선택한 파일을 읽는다.
- [ ] 사진 helper의 완료를 기다린다.
- [ ] 반환값을 미리보기에 표시하고 등록 시 사용할 값으로 보관한다.
- [ ] 사진 처리 실패를 화면에 표시한다.
- [ ] 사진 준비가 끝나기 전에 등록하지 않도록 한다.

### B-8. Hotplace 등록·조회·복원

이름·주소·유형·방문일·설명·사진·좌표를 읽어 검증합니다. 좌표는 우선 직접 입력합니다.

```text
현재 회원 확인
→ 입력·사진 준비 여부 확인
→ 회원당 3개 제한 확인
→ ownerId를 포함해 저장
→ 본인 목록 다시 표시
→ 지도 helper에 위치 전달
```

- [ ] 필수 입력값과 사진 준비 여부를 확인한다.
- [ ] 빈 좌표를 검사한 뒤 숫자로 변환하고 범위를 확인한다.
- [ ] 현재 회원 ID를 소유자로 저장한다.
- [ ] 현재 회원의 기록만 목록에 표시한다.
- [ ] 지도를 사용할 수 있으면 해당 기록의 좌표를 전달한다.
- [ ] 새로고침 후 사진·설명·방문일·위치가 복원되는지 확인한다.
- [ ] 다른 회원으로 로그인하면 그 회원의 기록만 표시한다.

삭제·주소 검색 연결은 시간이 남으면 추가합니다.

## 두 사람이 함께 지킬 연결 약속

- B가 저장·세션 함수를 먼저 제공하고, A는 그동안 JSON 조회와 목록 표시를 진행합니다.
- Storage 키와 데이터 필드는 [데이터 계약 문서](DATA_CONTRACT.md)를 그대로 사용합니다.
- 실제 `submit` 이벤트와 `preventDefault()`를 작성한 뒤 `data-preview-form`을 제거합니다.
- 해당 동작을 구현한 뒤 비활성 버튼의 `disabled`를 제거합니다.
- 마지막 25분에는 한 브라우저에서 두 계정으로 로그인해 데이터 분리와 새로고침 복원을 확인합니다.
- 실제 관광 API·드래그앤드롭·지도 키가 없는 상태의 지도 기능은 완료로 기록하지 않습니다.

180분 진행 순서와 담당 파일은 [역할 분담 문서](TEAM_ROLES.md)를 참고합니다. 처음 시작할 작업은 **A: JSON 읽기, B: 저장 함수 작성**입니다.
